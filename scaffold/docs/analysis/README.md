# Analysis

Explanations, reviews and proposals written for people: how something works, what is wrong with
it, what could change. An analysis is dated and frozen once merged, and it is not authoritative:
when it disagrees with the code, a design doc or an accepted ADR, those win.

- **Name**: `YYYY-MM-DD-<kebab-name>.md`, dated the day it was written.
- **Write for a person**: start with the idea and add detail after it. Prefer tables, plain words
  and short options (A or B) for decisions.
- **Not here**: the current state (`docs/design/`), a decision (`docs/decisions/`), a change plan
  (`specs/`).
